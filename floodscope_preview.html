User guide

Run a real analysis locally

This standalone HTML file is an offline dashboard preview. To process raw satellite data, run the included Python/Streamlit app from the project folder.

python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
PATH 01 · ONLINE

Fetch from Copernicus

In Streamlit choose Run an analysis → Fetch raw satellite data from Copernicus. Enter CDSE OAuth client credentials; choose a verified WGS84 bbox, event date and an OSM snapshot strictly before the event. The challenge case uses 2026-08-26 and the brief's 2026-07-27 snapshot. The starter bbox must be checked and edited.

PATH 02 · UPLOAD

Use prepared GeoTIFFs

Upload aligned pre/post Sentinel-1 files (band 1 VV, band 2 VH, optional band 3 dataMask) plus pre-event OSM GeoJSON. Inputs must share the same projected CRS, transform and dimensions. Optional Sentinel-2 files use Green, NIR, SCL and optional dataMask bands.

CHECK · SCENE PAIR

Audit the provenance

Inspect product IDs, dates, relative orbit, direction, resolution, OSM snapshot date and optional optical coverage. The online adapter refuses to compare Sentinel-1 scenes when a same-track pair cannot be confirmed.

OUTPUT · REPORT

Review and export

Toggle water, surface-change, road, asset and settlement layers. Ask supported map questions in English or Nepali. Export the report, analysis JSON, GeoJSON layers and water mask GeoTIFF. Treat all hits and cut-offs as candidates only.

Before using a case-study result: the challenge PDF supplies the specification, not the raw Sentinel scenes, OSM extract or EMSR927 reference layer. This project does not claim a real Trishuli result. Use EMSR927 only in a separate validation step, never as a detection input.
Method & limitations

Candidate evidence, never a damage verdict

The live Python pipeline uses transparent change rules and preserves source metadata. This HTML page visualizes only an invented fixture.

LayerRule / meaningWhat it cannot establish
New-water candidateLow post-event Sentinel-1 VV in dB, a negative VV change, and supporting VH evidence; optional cloud/SCL-masked Sentinel-2 NDWI change.Does not uniquely distinguish floodwater from wet soil, permanent water, shadow or other conditions.
Surface-change watchLarge VV/VH backscatter change not already labeled as water.May include debris, bank change, landslide, vegetation, agriculture or radar-geometry effects.
Asset overlapPre-event OSM buildings, highway ways and bridge tags intersect candidate polygons.Does not prove structural damage, occupancy, passability or current condition.
Potential isolationRoad graph edges intersecting water candidates are removed; mapped settlements are tested against mapped towns/hospitals.Not a safe-route product; OSM omissions and simplified topology can create misses or false cut-offs.
CopilotBounded English/Nepali templates insert values from map outputs only and abstain on unsupported intents.Not a general chatbot; no casualties, population, medical status or live field data are known.
Sentinel revisits are separated by days; this system cannot warn minutes ahead of a glacier collapse. Himalayan relief creates radar shadow/layover, clouds can remove optical evidence, OSM may be incomplete, and candidate thresholds can produce false positives and misses. Do not use this prototype as the sole basis for evacuation, rescue dispatch, aid allocation or declaring routes safe.
Data rules & validation

Keep detection and reference data separate

The app is designed around the challenge's input rules: Sentinel data, Copernicus DEM and a pre-event OSM snapshot for detection; published impact maps only for independent checking.

ALLOWED DETECTION INPUTS

Satellite + dated map

Sentinel-1 GRD is the primary cloud-robust change source. Sentinel-2 is optional optical evidence when clear. OSM is fetched from ohsome at a time before the event; pad the road-network context to include nearby services.

REFERENCE ONLY

EMSR927 / UNOSAT

These published products are not fetched or fed into the detection pipeline. The repository includes an isolated offline comparison script and blank scorecard for reviewer-provided reference data after a system mask is saved.
